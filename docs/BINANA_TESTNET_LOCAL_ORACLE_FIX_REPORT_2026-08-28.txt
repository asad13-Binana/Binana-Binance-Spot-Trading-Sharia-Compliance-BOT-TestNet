   payload.

   universe enrichment and Sharia discovery. The guarded Sharia launcher
   refuses startup when enabled processes can collectively exceed the shared
   ceiling. The keyless CoinGecko Sharia path is clamped to five calls/minute.
   Keys are never returned by the validator.

   TOOLING_UNAVAILABLE, COLLECTION_FAILED, TEST_FAILED and TIMEOUT statuses.
   Runtime dependency closures remain hash-locked and install into a disposable
   venv outside the checkout.

   four-bot target: ARM64 by default, at least 2 CPUs, 11,264 MiB physical RAM,
   14,336 MiB RAM+swap, and 80 GiB free root storage at bootstrap. AMD64 now
   requires an explicit reviewed override. Active deployment documentation now
   uses the collision-free binana-testnet paths and Oracle-only target.
8. Added a non-core discovery-to-owner-review bridge. It accepts only
   digest-valid VERIFIED_CANDIDATE records whose Binance market, provider ID,
   ticker, official host and HTTPS source URLs remain exactly bound. It writes
   a creation-only request with every identity_match=false and no trade
   permission. The 37-file protected inventory, including the complete Sharia
   service/discovery/rules/registry/runner set, remains byte-identical.
9. Replaced the Telegram command wall with a compact five-section owner panel,
   in-place callback navigation, explicit danger/primary controls and a safe
   presentation-only send fallback. Plain tickers such as SOL, SOLUSDT and
   SOL/USDT now reach the existing signed manual-scan path.
10. Added bounded Sharia batches of 10, 25, 50 and 100 without changing the
    protected screener service. The Telegram broker reads the existing
    hash-validated current universe and emits one exact signed low-priority
    request per selected base. The existing scan-ALL path is unchanged and
    still requires separate confirmation.
11. Added a read-only owner-panel registry summary that validates persistent
    entries and digest-valid discovery candidates independently of backend
    liveness. An empty registry is now displayed as operationally BLOCKED;
    discovery candidates still cannot self-authorise.
12. Made a rejected CoinGecko free Demo credential actionable as
    free_demo_key_rejected_or_not_enabled without printing the key or changing
    to a paid endpoint.
